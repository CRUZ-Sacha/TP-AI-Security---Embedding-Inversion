# AI Security — Embedding Inversion

Text embeddings are widely used in production systems (vector databases, RAG, semantic search) and are often treated as opaque vectors — safe to store and transmit. This project demonstrates that **personal information can be recovered from embeddings alone**, without access to the original text.

Three attack strategies are implemented, from the simplest to the most powerful.

---

## Dataset

**Source** : PAED / ConvAI2 — 35,030 persona sentences extracted from real chatbot conversations.

Each sentence is composed as `"[Name]. [original conversational sentence]"` and annotated with structured labels:

| Column | Example |
|---|---|
| `text` | `"I'm Sacha. I listen to rap music every day"` |
| `name` | `Sacha` |
| `relation` | `like_music` |
| `object` | `rap` |

100 unique names · 105 relation types · 3,259 unique objects.

---

## The Three Attacks

### 01 — Adaptive Probing
The attacker intercepts one embedding and iteratively tests semantic hypotheses. Starting from the known target identity, they generate small sets of probes, embed them with the same model, measure cosine similarity, and refine. No training required — fully manual and interactive.

### 02 — MLP Attribute Extraction
A neural network trained on `(embedding → name, relation, object)` triples. Once trained, it extracts structured attributes from any intercepted embedding instantly — no probe crafting needed.

```
Input (768-dim)
    ↓
Linear(768→256) → ReLU → Dropout(0.2) → Linear(256→128) → ReLU
    ├── head_name     → 100 classes
    ├── head_relation → 105 classes
    └── head_object   → 3,259 classes
```

### 03 — Generative Reconstruction Baseline
Frames the attack as full text reconstruction : find the closest sentence in a large corpus and measure semantic similarity. Also introduces **vec2text** as the state-of-the-art upgrade — a generative decoder that reconstructs text token by token from an embedding, with no corpus constraint.

## Project Structure

```
data/
  sentences_train_text_db.parquet         # public training database (text, name, relation, object)
  sentences_train_vector_db.index         # FAISS index — 35,030 vectors × 768 dimensions
  sentences_target_text_db.parquet  # target database (target_id, text)
  sentences_target_vector_db.index  # FAISS index — 5 target vectors × 768 dimensions
  target_sentences.txt              # 5 TP sentences in TARGET_ID : sentence format
  PAED/                             # source dataset (ConvAI2 persona annotations)

00_data_preparation.ipynb           # build all databases (run first)
01_adaptive_probing.ipynb           # manual iterative hypothesis testing
02_mlp_attribute_extraction.ipynb   # trained MLP extracts name / relation / object
03_generative_baseline.ipynb        # nearest-neighbor corpus search + vec2text
```

---

## Practical Session

`data/target_sentences.txt` contains 5 hand-crafted sentences identified as `OCTO1`–`OCTO5`. Notebook 00 embeds them into a dedicated target database. Each attack notebook selects one target by ID (`TARGET_ID = "OCTO1"`) and tries to recover what that person said — without ever reading the hidden sentence until the final reveal step.

## Installation

**Requirements** : Python 3.12+, [uv](https://docs.astral.sh/uv/)

```bash
# Clone the repository
git clone <repository-url>
cd AI_Security_Embedding_Inversion

# Create virtual environment and install dependencies
uv sync

# Launch Jupyter
uv run jupyter notebook
```

Then run the notebooks in order, starting with `00_data_preparation.ipynb`.

> All data files are generated by notebook 00. Run it first. Target files (`sentences_target_text_db.parquet`, `sentences_target_vector_db.index`) are also built by notebook 00 from `target_sentences.txt`.
